## Objective
Extend `.github/workflows/epic-traceability-lint.yml` (currently exits early when the issue is not `type:epic`) so that when a **child ticket is closed**, the workflow resolves the **parent Epic** and re-runs epic-traceability validation on it.

## Rationale
The current implementation fires on all issue events but only validates when the issue itself is an Epic. Side effect: if a child closes and the parent Epic body never had the child reference, no automated event re-validates the Epic, so the drift goes unnoticed until someone manually edits the Epic.

## Drift remediation (2026-06-28 Manager review)
The original AC specified parent resolution via prose `Epic: #N` / `Parent: #N`. Two drifts since 2026-05-12:
1. **Sub-issues became the canonical parent/child primitive.** `scripts/global/lint-epic-drift.js#resolveParentEpic()` already resolves the native parent via GraphQL `parent{number}`. Parent resolution MUST therefore be **native-sub-issue-parent-first**, prose-fallback (mirrors the closeout-schema "prefer Sub-issue link over prose-scan" precedent).
2. **The repo's actual prose convention is `Refs Epic #N`** (this very ticket uses it), not `Epic: #N`/`Parent: #N`. The prose fallback MUST accept `Refs Epic #N`, `Epic: #N`, and `Parent: #N`.
