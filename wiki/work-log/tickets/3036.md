## Body

## Problem (F-CL2, F-LS3)
cross-team-queue first-claim-wins uses comment timestamps (not atomic CAS) -> two teams both 'win' under clock skew. merge-claim release does two sequential KV deletes (non-atomic); GitHub-label fallback acquire is idempotent-no-op (both teams win).

## ACs
- AC1: replace timestamp first-claim-wins with ref-CAS/atomic claim — the CROSS-RUNNER/distributed primitive (GitHub-native git ref compare-and-swap, or API conditional request with ETag/If-Match) for the Tier-1 default; local flock is the Tier-0 (single-machine) fallback only. Local flock is NEVER used as the cross-team/distributed claim guard.
- AC2: idempotent merge-claim release (no orphaned claim-id on partial failure); every distributed CAS / conditional request uses bounded exponential-backoff retry on transient failure (incl. 429 / 5xx) and on exhaustion FAILS CLOSED (no claim granted) + emits a degradation event — never a silent grant or silent degradation.
- AC3: label-fallback acquire uses a CAS-equivalent (no double-win).

## Success metric: two concurrent claims on one ticket -> exactly one winner; idempotent release leaves no orphan.
