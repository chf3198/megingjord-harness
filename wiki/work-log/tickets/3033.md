# #3033 — C5: Atomic coordination primitives for shared state + lease liveness

## Body

## Problem (F-LS1, F-LS2, F-LS4, F-WT1, F-LG2, F-LG3)
state_store.save_state, cross-team-lease-registry write, and JSONL emitters are non-atomic read-modify-write (no flock/atomic-rename) -> lost updates / torn files / lost leases under concurrent teams. Crashed-team lease blocks others ~24h. No cross-team lease pre-push gate (#2916). Log-rotation rename->write window drops emits.

## ACs
- AC1: ONE reusable atomic primitive (atomic-rename / with-file-lock, timeout + fail-closed) consumed by state_store, cross-team-lease-registry, JSONL emitters (DRY). CONCURRENCY-DOMAIN: this primitive guards the LOCAL-PROCESS domain only (multiple agents on ONE machine). It is NEVER used to guard a cross-runner/distributed surface — the cross-team-lease-registry's AUTHORITATIVE copy is the GitHub-native ref/issue (distributed CAS, see C8); the local file is a cache reconciled from it.
- AC2: ship the cross-team-lease pre-push blocking gate — **subsumes & closes #2916**, carrying forward its specifics (cross-team-lease-check step in lefthook.yml pre-push; cross-team path defs in config/governance-rules.yaml; MEGINGJORD_IT_OPS=1 bypass preserved). *(Consolidated 2026-06-23.)* Adjacency: #1934 (state-store path parity) + #2275 (post-merge state reconciler) share the state_store surface — C5 owns ATOMICITY; coordinate edits.
- AC3: bounded, observable heartbeat reaper for crashed-team leases that VALIDATES a candidate-stale lease against the GitHub-native authoritative registry before reaping (never reaps a live remote lease; no zombie agent on stale-local).
- AC5: local lease/claim cache is RECONCILED from the GitHub-native authoritative copy on every read; on divergence authoritative wins and the stale local entry is dropped with an observable event.
- AC4: log-rotation creates the empty hot file before rename (no mid-emit drop).
