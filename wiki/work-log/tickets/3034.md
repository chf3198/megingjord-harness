## Body

## Problem (F-CL1, F-RR1)
label-lint auto-transition reads issue once then applies sequential remove/add with no re-read -> concurrent team label edits violate single-status/single-role. derive_roles_from_github serves stale cache to 300s -> permission-mismatch under concurrent edits + outage.

## ACs
- AC1: read-before-write / optimistic-lock in label-lint via the GitHub API CONDITIONAL-REQUEST mechanism (ETag / If-Match, or re-read-and-compare-before-write) — label-lint runs on DISTRIBUTED Actions runners, so a local flock cannot coordinate it; abort + advisory on concurrent drift; bounded exponential-backoff retry on transient failures incl. 429 rate-limit / 5xx, then deterministic advisory-abort (never livelock, bounded liveness); fail CLOSED and surface on exhaustion (never silent grant); serialize per-issue.
- AC2: bound derive_roles stale window + emit a stale-decision flag operators can see.

## Success metric: two concurrent label edits never yield multi-status/multi-role; no livelock under contention.
